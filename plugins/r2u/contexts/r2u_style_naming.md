## 指令(做什么)

在本工作区内**新建或修改代码与相关文本**时，各类标识符与文件的命名风格应与 **C++ 标准库（std）** 中公开 API 的常见约定保持一致（以标准头文件中暴露的名称与主流实现习惯为准）。

## 约束(怎么做)

### 类型命名

包括但不限于：类、结构体、`enum` / `enum class`、类型别名、`using` 类型名、`concept` 等。

- 采用与 std 中类型名一致的 **`snake_case`、全小写、多词以下划线连接** 的风格。
- 示例（摘自标准库常见名称，仅作风格参照）：`vector`、`string`、`unordered_map`、`optional`、`shared_ptr`、`size_t`、`input_iterator`。

### 变量命名

包括但不限于：局部变量、成员变量、函数参数、非宏常量对象等。

- 同样采用 **`snake_case`、全小写**；与 std 文档及算法描述中常见标识符风格一致。
- 示例：`first`、`last`、`mid`、`count`、`result`、`value`、`index`。

### 函数与函数式实体

- 自由函数、成员函数、运算符（在命名相关约束上按「与类型/变量同一套 snake_case 体系」处理）、函数对象类型名等，均与 std 中 `push_back`、`emplace`、`sort` 等命名风格一致。

### 命名空间

- 与 std 次级命名空间习惯一致：**全小写**、简短、多词可用下划线或单一层次嵌套（如标准中的 `chrono`、`filesystem`、`ranges`），避免 StudlyCaps 或与 `std` 易混淆的名称。

### 宏

- 标准库自身极少对用户提供宏；**优先不用宏**。若必须定义，须避免标准保留形态（如含双下划线、以下划线加大写字母开头等），并采用业界与 std 周边常见且不冲突的 **`SCREAMING_SNAKE_CASE`**（全大写+下划线），且仅用于真正需预处理器的场景。

### 代码文件命名

- 头文件与源文件名采用 **`snake_case`**，扩展名与项目现有约定一致（如 `.h`、`.hpp`、`.cpp` 等），与标准库头所体现的「小写、下划线分词」习惯一致（如 `type_traits`、`unordered_map` 所对应的文件名风格）。

### 其他

凡本文未逐条列出的标识符或文件命名（如模板非类型参数、私有实现细节符号等），**默认仍以 std 公开表面所体现的风格为准**：以 `snake_case` 与小写命名空间为主，避免与标准保留规则冲突；不引入与 std 惯例明显不一致的 StudlyCaps 或匈牙利命名等，除非项目内已有与之冲突的既有规范且用户明确要求仅改局部。

## 说明

- 本规则是**风格对齐**，不要求名称与 std 中已有符号重复或模仿其实现细节命名。
- 若与项目内其他专用规则冲突，以**更具体且标明适用范围**的规则为准。
