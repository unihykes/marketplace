## 指令(做什么)

在本工作区内**新建或修改 C++ 源码**时，在**不改变语义、不违背项目已锁定的语言标准**的前提下，应**优先选用现代 C++ 惯用法**；能选更高标准特性时，按下列**语言标准优先级**取舍（从高到低）：

**C++20 > C++17 > C++14 > C++11 > C++03 > C++98**

即：在可选场景下，优先使用较新标准为解决问题而引入的语法与库设施；若项目或编译目标仅支持某一较低标准，则在该标准允许范围内仍应尽量采用该世代及之前的「现代」写法，而非退回更早的 C 风格或预标准习惯。

**适用范围**：`*.cpp`、`*.hpp`、`*.h`、`*.cc`、`*.cxx` 等 C++ 源文件；与更具体且标明适用范围的规则冲突时，以更具体的规则为准。

## 约束(怎么做)

### 一般原则

- **可选才优先现代**：若旧写法与新写法在可读性、性能、ABI、可移植性上无实质劣势差异，优先新写法；若旧写法在约束（如裸指针互操作、指定 ABI、嵌入式工具链）下更稳妥，则服从项目与用户要求，不强行「为现代而现代」。
- **标准上限**：不得使用**高于**项目 `CMakeLists.txt`、编译选项或文档所声明的 C++ 标准；本规则是在**已允许的标准内**向上对齐，而非单方面抬高标准。

### 推荐方向（示例，非穷尽）

在标准允许时，可优先考虑下列一类写法（示例仅说明方向，具体以项目标准为准）：

| 方向 | 示例 |
| --- | --- |
| 类型推导 | 在类型冗长且明显时优先 `auto`；配合初始化避免窄化 |
| 编译期常量 | `constexpr`、`consteval`（C++20）、`if constexpr` 等 |
| 空指针 | `nullptr` 替代 `(T*)0` 或 `NULL` |
| 函数式与局部逻辑 | 就地 `lambda`、算法配合 lambda，替代仅用于一处的大块手写循环（在可读性不下降时） |
| 迭代 | 范围 `for` 在语义等价且更清晰时优先于手写下标循环 |
| 虚函数与接口 | 派生类对虚函数使用 `override`（及必要时 `final`） |
| 所有权与资源 | 智能指针、`std::optional` / `std::variant` / `std::span`（C++20）等，替代裸 `new/delete` 或易错的手动生命周期（在 API 允许时） |
| 并发与同步 | `std::jthread`（C++20）、`std::atomic` 惯用法等，优于仅因习惯而保留的旧式线程接口（在平台支持时） |

### 不推荐

- 为使用新特性而牺牲**可读性**（例如过度 `auto` 导致类型不可辨）。
- 在团队已统一禁止某项特性的情况下仍强行使用（以项目约定为准）。

## 说明

- 「现代」指各标准引入的惯用语义与库，而非某一编译器扩展；非标准扩展须在项目明确允许时使用。
- 本规则与「对齐 std 命名与格式」等风格规则互补：现代写法仍须遵守既有命名与排版约束。
